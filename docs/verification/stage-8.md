# Этап 8: публичные плейлисты

Ветка `feature/stage-8-playlists` создана от `work` на `cd8109b`.
Проверки выполнены в локальной облачной среде, PostgreSQL 17 и Chromium
156.0.8078.79. GitHub Actions, Firefox/Safari и нагрузочные испытания не заявляются.

## Реализация

- Модуль `app/playlists`, миграция 0009: playlists и playlist_items. Составной PK
  исключает повтор видео, CHECK запрещает отрицательные позиции. Уникальность
  playlist_id/position DEFERRABLE INITIALLY IMMEDIATE позволяет перестановку
  одной транзакцией. Удаление плейлиста каскадно убирает только его элементы.
- Создание, переименование и удаление своих списков; идемпотентное добавление/
  удаление видео; перемещение перед доступным элементом или в конец.
  Все изменения защищены владением, сессией, CSRF и PostgreSQL-лимитами.
- Публичные метаданные и элементы; `visible_count` и содержимое везде
  фильтруются общей `viewable_by`. Скрытые/удалённые/неготовые видео исключены
  для всех, private видят только владельцы видео и получатели grants.
  Владение плейлистом, подписка и роль не расширяют доступ к видео.
- Изменения берут FOR UPDATE плейлиста; страницы элементов — FOR SHARE.
  Добавление и перемещение блокируют нужные видео по UUID, затем повторно
  проверяют ACL. Удалить членство можно и после отзыва разрешения на ролик.
- Пагинация метаданных по created_at/id, элементов — по внутреннему порядку.
  Сырые позиции и полное число скрытых элементов не публикуются. HMAC-подпись
  защищает курсор от подмены якоря; непубликуемая revision служит ключом,
  её публичный tag не позволяет восстановить ключ. Смена состава/порядка даёт
  старому курсору 409; отзыв ACL перепроверяется независимо от курсора.
- `/my-playlists`, `/playlists/{id}` и раздел на канале с независимой
  пагинацией. Добавление по ссылке на видео; «Выше»/«Ниже» учитывают якорь
  следующей страницы даже при limit=1. Ошибки сохраняют название/ссылку,
  ручное обновление не стирает черновики. Плейлист не удаляет исходные видео.
- Настройки PLAYLIST_CREATE_LIMIT_PER_HOUR=30, PLAYLIST_WRITE_LIMIT_PER_MINUTE=120,
  PLAYLIST_MAX_ITEMS=1000 (допустимо 1–10000); ограничения доступны в Compose.
  Название — 1–200 символов, null/extra/NUL/непарный суррогат отклоняются с 422,
  корректные emoji и HTML-подобный текст отображаются безопасно.
- Swagger/контракт дополнены одиннадцатью операциями. Readiness проверяет новые
  таблицы; страницы и API имеют no-store/Vary: Cookie.

Браузерные сценарии используют отдельный `stage8-verify` на localhost:8093,
миграционная проба — пустую `stage8_migration_probe`. Команды и артефакты:
[experiments/README.md](../../experiments/README.md).

Downgrade 0009 удаляет только плейлисты и их состав. Повторный upgrade создаёт
пустые таблицы; для сохранения списков при откате нужна резервная копия.
Проверки маленьких видео и списков не подтверждают максимальную нагрузку.
Приватность применяется к новым запросам; уже полученные данные отозвать нельзя.

## Исправления после повторной проверки

- Обновление плейлиста синхронизирует нетронутое поле названия с сервером.
  Настоящий черновик сохраняется; возвращение к последнему серверному значению
  снова делает поле чистым. Сохранение не возвращает прежнее название из другой вкладки.
- Подтверждённое добавление/удаление/перестановка/очистка отделены от чтения
  результата. Во время обновления счётчик неизвестен, а успешная запись уже
  подтверждена. При GET 503 показывается подтверждение и предложение обновить
  список без повторной записи. Старые карточки и неверные счётчики не остаются.
- При подтверждённом чтением 404 управление удалённым плейлистом скрывается и
  отключается, появляется ссылка к своим спискам. Write 404 проверяется публичным
  чтением, чтобы отличать отсутствие списка от утраты прав управления.
- «Убрать недоступные видео» доступно владельцу с подтверждением. DELETE
  unavailable-items идемпотентно освобождает занятые места, сохраняя сами видео,
  media и другие списки. Нет автоматической очистки или раскрытия скрытых ID/количества.
- Вход и регистрация отклоняют непарные суррогаты в пароле с 422 до Argon2.
  Пароль не отражается в ошибке, не обрезается и не нормализуется; корректные
  Unicode, NUL и пробелы сохраняют прежнюю совместимость.

Добавлены девять интеграционных тестов: ошибка Unicode в обоих auth endpoints,
точное сохранение пароля, очистка/идемпотентность/CSRF/владение, освобождение
лимита и реальное ожидание блокировки при выдаче/отзыве grant во время очистки.
Новые таблицы и миграции для исправлений не нужны, схема остаётся 0009.
Восстановления UI проверяет `playlist_recovery_browser_probe.cjs` на отдельном
`stage8-fixes` с лимитом одного элемента; обычный сценарий плейлистов — на
отдельном `stage8-verify`. Команды описаны в experiments/README.md.
