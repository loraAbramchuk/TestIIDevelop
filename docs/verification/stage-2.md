# Проверки этапа 2: метаданные и доступ

Ветка: `feature/stage-2-videos-access`, создана от `work` на `01ca1d3`.
Результаты локального экземпляра среды; статус GitHub Actions здесь не подтверждается.

## Реализовано

- `app/videos`: модели, общая SQL-политика, прикладные операции, router и страницы.
- Миграция 0003: videos и video_grants, внешние ключи, уникальный составной ключ
  разрешения, проверки состояний и готовых метаданных, индексы владельца и grants.
- Создание своих метаданных с private/uploading по умолчанию; редактирование
  только title/description/visibility; статусы и ошибки доступны владельцу.
- Выдача/отзыв доступа существующему пользователю, стабильная пагинация своих
  карточек и grants с курсорами, привязанными к владельцу/видео.
- Проверка ready + visible + not deleted + public/owner/grant одним SQL-предикатом.
- Страницы `/studio`, `/studio/videos/{id}` и ссылка «Мои видео» после входа.
- Общие CSRF и PostgreSQL-rate limits вынесены из auth router в auth_protection
  и применены к новым изменениям; поведение авторизации сохранено.
- Действующий Swagger показывает только рабочие операции. Общий JSON-контракт
  отмечает x-implemented по router; файлы и удаление остаются проектными.

Прошли Ruff, проверка форматирования, актуальности JSON-контракта, синтаксиса JS,
ссылок и блоков Markdown. Временные PostgreSQL с тестовыми данными и отдельный
процесс браузерного приложения после проверки остановлены и удалены. Проверки
не создавали тестовые аккаунты в основной БД разработки.

Команды из корня (нужна отдельная PostgreSQL и её настройки через env):

```bash
uv run --locked alembic upgrade head
uv run --locked alembic check
RUN_DB_TESTS=1 uv run --locked pytest
uv run --locked python scripts/export_video_contract.py --check
uv run --locked ruff check app migrations tests scripts experiments
uv run --locked ruff format --check app migrations tests scripts experiments
```

Браузерный сценарий создаёт тестовые аккаунты и карточку. Только для приложения,
подключённого к отдельной тестовой БД, со штатным Playwright и Chromium:

```bash
STUDIO_TEST_BASE_URL=http://127.0.0.1:8012 node experiments/studio_browser_probe.cjs
```

Он не заменяет матрицу прав pytest: в браузерном сценарии файл ещё не загружен,
поэтому grantee не может посмотреть карточку uploading даже с разрешением.

## Ограничения

- Нет приёма файлов, реального worker, превью и stream. VideoView содержит
  зарезервированные адреса этих будущих маршрутов, а не работающие медиассылки.
- Готовые/скрытые/удалённые состояния создаются тестовыми фикстурами. Клиент не
  умеет назначать ready. Проверки приватных байтов и Range — этап 5.
- Нет DELETE video: его реализация требует очереди очистки и хранения файлов.
- Нет каталога, каналов, социальных функций, панели модератора/администратора.
- Firefox/Safari не проверены; поддержка дополнительных браузеров не заявляется.
- Downgrade 0003 удаляет новые таблицы и данные видео; это не безопасный способ
  отката production без согласованной резервной копии.
