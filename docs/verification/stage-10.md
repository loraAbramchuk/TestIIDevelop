# Этап 10: администрирование пользователей

Ветка `feature/stage-10-administration` создана от `work` (`326ec70`).

## Реализация

- `/admin/users`: список с поиском имени/email, фильтром роли и keyset-пагинацией.
  Администратор назначает user/moderator/admin с обязательной причиной.
- Четыре API, отдельные страницы и история `/admin/audit`, только admin.
  Пользователь и модератор не получают административные email/карточки/историю.
- Транзакционный advisory mutex перед row locks сериализует API-изменения ролей;
  исполнитель читается заново под FOR SHARE, цель — FOR NO KEY UPDATE. Проверка
  последнего admin, смена роли и запись аудита выполняются атомарно.
- Понижение последнего администратора запрещено, включая параллельные попытки.
  Взаимное понижение двух admin даёт одно изменение и отказ утратившему права.
- Существующая сессия немедленно учитывает новую роль при новом запросе.
  Самопонижение на экране подтверждается, управление закрывается без выхода
  из аккаунта. Регистрация и профиль не назначают привилегии.
- Повышение роли не создаёт grant и не открывает private/hidden видео.
- User.role_changed содержит UUID исполнителя/цели, причину и previous_role/role.
  Административная история отделена от четырёх действий модерации.
- changed=false сообщает о повторе без нового события, сохраняя текст.
  expected_role позволяет обнаружить устаревшую форму с 409 role_conflict;
  last_admin имеет отдельный код 409. Неполные ответы не подтверждают запись,
  ошибки чтения блокируют повтор записи до обновления, черновик сохраняется.
- CLI bootstrap сохранён: новый admin с каналом, существующий аккаунт не повышает.
  Нет предустановленных аккаунтов или паролей в основном приложении.
- ADMIN_WRITE_LIMIT_PER_MINUTE=30, сессия/CSRF, no-store/Vary: Cookie.
  Миграция 0011 добавляет только два индекса users для списка/фильтра по роли.

Браузерные аккаунты находятся только в отдельных `stage10_browser` и
`stage10_fixes_browser` на localhost:8097;
миграционные пробы используют пустые БД с суффиксом `_probe`. Команды и артефакты:
[experiments/README.md](../../experiments/README.md).

Индексы не требуют изменения старых данных; downgrade сохраняет роли и аудит.
При возврате старого кода нужно сохранять фильтрацию типов аудита: прежняя общая
выдача не должна открывать историю назначения ролей модераторам. Изменения ролей
напрямую через административный SQL находятся вне защиты API-mutex. Нагрузочная
проверка и Firefox/Safari в этом этапе не выполнялись. Образцы private/hidden
в браузерной пробе проверяют запрет доступа. После исправлений отдельно проверены
нативное воспроизведение и перемотка через Nginx, upload/worker, grant/revoke,
переключение public/private и удаление; pipeline также покрыт полным pytest.


## Исправления после повторной проверки

- Выбор роли становится чистым при совпадении с ответом сервера. Следующее
  назначение из другой вкладки отражается и в подписи, и в select. Отличающийся
  несохранённый выбор и причина сохраняются.
- Общий JSON helper ограничивает fetch и чтение тела 15 секундами через
  AbortController. request_timeout не подтверждает запись; PATCH не повторяется.
  Панель читает текущие сведения, сохраняет причину и неопределённый результат.
  При таймауте GET управление записью отключено, кнопка обновления доступна.
  Предварительный GET csrf тоже ограничен: при его таймауте PATCH не отправляется.
- CSRF имеет отдельный код csrf_invalid. Любой 401/403 в панели вызывает проверку
  текущего аккаунта: действующий admin получает обновление карточки с сохранением
  черновика, утрата роли/сессии закрывает панель. Ошибка или неполный ответ проверки
  сессии отключает запись, сохраняя карточки и возможность повторить чтение.
  Подтверждение другого аккаунта требует заново открыть панель.
- Обработка request_timeout подключена к восстановлению форм модерации и жалоб,
  использующих общий helper. Миграции не нужны, схема остаётся 0011.

Два новых интеграционных случая проверяют отсутствие/устаревший CSRF: 403 с кодом,
сохранение роли admin, отсутствие изменения цели/аудита, затем успешную запись с
правильным токеном. Дополнительный браузерный модуль проверяет чистый/несохранённый
выбор, реальный CSRF-отказ, malformed/503 проверки сессии и ручное восстановление.
Проверены настоящие 15-секундные зависания PATCH до выполнения и после commit,
GET карточки и csrf preflight, а также JSON body при уже полученных заголовках.
Счётчики запросов и событий подтверждают отсутствие автоматического повтора.

Регрессия общего helper: `playback_browser_probe.cjs` прошёл через Nginx на
изолированном localhost:8095 с настоящим MP4, JPEG, seek и удалением (204).
