# Этап 6: каталог, каналы и подписки

Ветка `feature/stage-6-catalog-channels` создана от `work` на `84e1a55`.
Проверки выполнены в локальной облачной среде. GitHub Actions, Firefox, Safari
и нагрузочные испытания в этот результат не включены.

## Реализация

- Миграция 0007 добавляет channels и subscriptions. Существующие пользователи
  получают по одному каналу; регистрация и CLI создают аккаунт и канал одной
  транзакцией. Профиль имеет название, описание и неизменяемого владельца.
- `/` и `/search` показывают только публичные ready/visible/неудалённые видео,
  включая для владельца. Карточки содержат защищённое превью и ссылку на автора.
  Поиск по части названия использует ILIKE с экранированием шаблонных символов.
- `/channels/{id}` использует общую политику просмотра: private доступно только
  владельцу и получателю grant; hidden/неготовые/удалённые исключены для всех.
  На странице просмотра добавлена ссылка на канал автора.
- Владелец меняет название/описание своего канала. Подписка и отмена идемпотентны,
  защищены CSRF и лимитами; уникальная пара не допускает дублей при гонках.
  Самоподписка отклоняется. `/subscriptions` возвращает только свой список.
  Количество подписчиков публично; список их аккаунтов не публикуется.
- Подписки не участвуют в ACL видео и не создают grants. Все списки ограничены
  limit 1–100 и используют keyset-курсор с привязкой к контексту выдачи.
- Новые страницы имеют пустые состояния, безопасные сообщения 400/404/422/503,
  no-store и Vary: Cookie. Формы сохраняют введённые данные при ошибке запроса.
  Общий API-помощник используется страницами каналов и прежнего управления видео.
- Контракт и Swagger дополнены восемью операциями каталога/каналов/подписок.
  Лайки, комментарии, плейлисты и экран модерации остаются последующими этапами.

Браузерные проверки выполнены в отдельном `stage6-verify` на localhost:8091,
миграционная — в пустой `stage6_migration_probe`. Пробы и команды повторения:
[experiments/README.md](../../experiments/README.md). Двухсекундные настоящие MP4
проверяют сценарий, но не подтверждают производительность на максимальных файлах.

Upgrade сохраняет существующие данные и идентификаторы созданных каналов при
повторном запуске. Downgrade удаляет channels/subscriptions; повторный upgrade
создаёт новые профили с новыми UUID. Этот эксперимент не подтверждает безопасный
откат пользовательских профилей без резервной копии.

## Исправления после повторного ревью

1. Регистрация с NUL в имени возвращала 503, изменение канала с непарным
   суррогатом — 500. Общая валидация отклоняет недопустимый текст с 422 до
   сохранения; применена также к названиям/описаниям видео. Корректные emoji
   сохраняются. Проверены отсутствие частичных записей и успешное исправление ввода.
2. Формы авторизации показывали SyntaxError при HTML-ответе от прокси. HTML,
   пустой ответ, JSON null и отсутствие CSRF теперь дают понятное сообщение;
   введённые данные сохраняются, кнопка доступна для повтора. Сетевые ошибки,
   JSON 429 и существующая обработка 422 сохранены.
3. Вход из канала раньше возвращал на главную. Адрес сохраняется в `next`
   при переходах между входом/регистрацией и после успешной авторизации.
   Защищённые страницы также передают свой адрес. Сервер отклоняет внешние
   адреса, обратные слэши, управляющие символы и их опасные URL-кодировки.

Добавлены 35 тестов для регрессий и адресов возврата, расширены проверки канала.
`auth_recovery_browser_probe.cjs` проверяет реальные регистрацию/выход/вход и
возврат к каналу после имитации сбоев. Каталог, поиск, подписки и grant/revoke
повторно проверены через Nginx/Chromium; ошибок JS нет. Команды и артефакты
приведены в [experiments/README.md](../../experiments/README.md).
