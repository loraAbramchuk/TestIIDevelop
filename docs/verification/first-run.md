## Изменения по обратной связи

Ранее конфигурация без SMTP приводила к `503 mail_unavailable` ещё до создания
аккаунта. Для обычной локальной проверки теперь используется Mailpit:
`MAIL_BACKEND=auto` выбирает заданный SMTP либо локальный ящик для loopback HTTP.
Launcher запускает его вместе с остальными сервисами и при необходимости
добавляет отсутствующий ключ писем, сохраняя прежние пароли и настройки.
На страницах и в выводе запуска есть адрес ящика. Регистрация и первый вход
не требуют редактирования SQL, назначения признака подтверждения или реального
почтового провайдера. Подтверждение и восстановление проходят через письма и
существующую очередь; неподтверждённый аккаунт не получает права менять контент.

Production overlay принудительно выбирает SMTP для всех четырёх прикладных
сервисов. Mailpit исключён из стандартного запуска этого профиля, при переходе
на SMTP launcher останавливает прежний локальный ящик. Неполный SMTP обнаруживается
до сборки и остановки writers. Mailpit UI/SMTP публикуются только на loopback,
образ закреплён manifest digest. Внешняя доставка реальному провайдеру не проверялась.

Добавлены `app/seed.py` и host-entrypoint `scripts/seed.py`. Явный `--demo`
создаёт четыре подтверждённых demo-аккаунта user/user/moderator/admin, четыре
канала, три публичных и один приватный MP4, превью, grant, подписку, лайк,
комментарий, плейлист и учебную жалобу. Файлы действительно генерируются FFmpeg,
передаются через upload API и обрабатываются worker. Повтор сохраняет пароли,
роли и существующие метаданные; коллизия email не повышает чужой аккаунт.
Произвольных очисток БД или удаления пользовательских файлов нет.

## Условия и границы

Воспроизводимый прогон: [first_run_probe.py](../../experiments/first_run_probe.py)
и [first_run_browser_probe.cjs](../../experiments/first_run_browser_probe.cjs).
Конфигурация генерируется с нуля; вручную меняются только изолированные порты,
БД и storage. Используются собственные PostgreSQL volume, Mailpit и Nginx.
API/worker работают на хосте; seed выполняется в Docker с теми же runtime
зависимостями. Из-за приватных прав workspace исходники копируются из read-only
mount внутрь одноразового контейнера, после чего UID/GID сбрасываются до 10001.
Это тестовый механизм доставки текущего кода, отдельная пересборка полного
Compose-стека в этой проверке не выполнялась.

На этом rootless Docker/VFS стенде создание контейнера копирует большой rootfs.
Поэтому для изолированного media используются резерв 128 МиБ, лимит файла
64 МиБ, квота автора 512 МиБ и общий бюджет 2 ГиБ. Настройки приложения по
умолчанию — резерв 2 ГиБ, файл 1 ГиБ, квоты 10/100 ГиБ — не уменьшались.
Все тестовые контейнеры/volume и медиа очищены. Основные `.env`, БД, media,
резервные копии и работающие контейнеры не обновлялись; diagnostics основного
сервиса после проверки — ok, хеш `.env` сохранён.

Артефакты успешного прогона:
`/tmp/first-run-review-6/first-run-results.json`, `browser-results.json`,
`tests.log`, `seed-first.log`, `seed-repeat.log`, `home.png`.
Санитизированный протокол: [first-run-results.json](first-run-results.json).
Секреты `.env`, captured mail и технические журналы в Git не добавлены.

Это локальная приёмка исправления из обратной связи. Проверки целевой Ubuntu
VM/systemd, публичного ACME, внешнего restore и настоящего SMTP остаются
отдельными условиями публичного выпуска. Ранее сохранённый отпечаток этапа 12
не объявляется актуальным протоколом нового дерева исходников.
