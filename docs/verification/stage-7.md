# Этап 7: лайки и комментарии

Ветка `feature/stage-7-interactions` создана от актуальной `work` на `e2d2dc4`.
Результаты относятся к локальной облачной среде, PostgreSQL 17 и Chromium
156.0.8078.79. GitHub Actions, Firefox/Safari и нагрузочные испытания не заявляются.

## Реализация

- Модуль `app/interactions`, миграция 0008: likes с составным PK video_id/user_id
  и comments с автором, видео, текстом до 2000 символов и индексом пагинации.
  Существующие таблицы и файлы миграция не изменяет.
- GET/PUT/DELETE likes, GET/POST comments, DELETE своего комментария.
  Доступ проверяется общей политикой видео до чтения счётчиков и записей.
  Гость читает публичные обсуждения, изменения требуют сессии и CSRF.
- Все изменения взаимодействий блокируют строку видео и затем проверяют ACL
  отдельным SQL-запросом. Запрос, дождавшийся отзыва доступа, не использует
  старое разрешение. Роли и подписки не дают дополнительных прав.
- Лайк и отмена идемпотентны; счётчики считаются по строкам, без отдельного
  изменяемого кэша. Удалять комментарий может только его автор при наличии
  доступа к ролику. Владелец видео не удаляет чужие комментарии.
- Комментарии сортируются по created_at/id по убыванию, limit 1–100 (20),
  keyset-курсор привязан к видео и посетителю; ACL перепроверяется на каждой
  странице. Ответ содержит канал автора и can_delete, не email.
- Пустой/слишком длинный текст, null, лишние поля, NUL и непарные суррогаты
  отклоняются с 422. HTML-подобный текст допустим и выводится через textContent.
- Отдельные настройки лимитов: INTERACTION_WRITE_LIMIT_PER_MINUTE=120 и
  COMMENT_CREATE_LIMIT_PER_MINUTE=10 на пользователя, PostgreSQL-счётчики,
  429 с Retry-After. Настройки доступны в Compose и .env.example.
- На `/watch/{id}` — лайк, счётчики, форма, список с «Ещё комментарии», удаление
  с подтверждением и ручное обновление. Черновик сохраняется при лайках,
  удалении, обновлении и ошибках. После отказа доступа обсуждение очищается.
  Потерянный ответ POST не вызывает автоматической повторной отправки.
  Удаление комментария в другой вкладке корректно обновляет список.
- Swagger и экспорт контракта содержат шесть новых операций; readiness
  проверяет новые таблицы. Лайки/комментарии не меняют media-пайплайн.

Сценарии выполнялись в отдельном `stage7-verify` на localhost:8092; миграция —
в пустой `stage7_migration_probe`. Команды повторения и артефакты:
[experiments/README.md](../../experiments/README.md).

Downgrade 0008 удаляет лайки и комментарии, сохраняя данные этапов 1–6. Повторный
upgrade создаёт пустые таблицы взаимодействий; для сохранения этих данных при
откате нужна резервная копия. Пробы с маленькими видео не подтверждают нагрузку
и работу с максимальными файлами. Уже полученные клиентом данные нельзя отозвать;
новые запросы после потери доступа блокируются.
