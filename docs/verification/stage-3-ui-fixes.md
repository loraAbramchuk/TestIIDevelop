# Исправления после проверки этапа 3

Ветка `feature/stage-3-video-upload`; продолжение коммита `8a79c00`.

- После подтверждённого приёма файла поля названия/описания/видимости и файл
  блокируются вместе с кнопкой передачи. Блокировка действует и при потерянном
  ответе, если сверка статуса показывает processing/ready. После неудачной
  передачи остаются редактирование и повтор той же карточки. Изменение метаданных
  принятого видео доступно через ссылку на страницу управления.
- Имя пользователя в шапке переносится и укладывается в ширину навигации.
  Допустимое имя из 100 букв без пробелов больше не расширяет мобильную страницу.
- `/docs` использует локальные JS, CSS и favicon Swagger UI 5.35.0. Онлайн-валидатор
  отключён. Добавлены неизменённые upstream-ресурсы, Apache-2.0 LICENSE/NOTICE и
  лицензии зависимостей bundle. SHA-512 архива сверена с npm distribution integrity;
  происхождение и обновление описаны в app/static/vendor/swagger-ui/README.md.

## Проверки

- PostgreSQL 17: полный pytest — 113 passed; прежнее предупреждение Starlette
  TestClient/httpx2. Новый тест проверяет доступность локальных ресурсов Swagger
  при размещении приложения за префиксом `/video`.
- Chromium 156: после реального 415 данные доступны для повтора; после 202 все
  поля формы передачи заблокированы; метаданные сохраняются через управление.
- Потеря ответа моделируется перехватом: реальный PUT сохраняет файл и задание,
  затем ответ браузеру обрывается. Статус processing корректно блокирует форму.
- Имя из 100 символов: нет горизонтального переполнения при 320/390/768/1440 px.
- Swagger при блокировке всех внешних запросов: 17 операций отрисованы, Try it out
  вызывает `/health/live` и получает 200/`{"status":"ok"}`. Внешних запросов и
  ошибок браузера нет; проверка выполняется также на Docker/Nginx экземпляре.
- Ruff, форматирование, актуальность OpenAPI-контракта и запуск Compose проверены.

Команды и сценарии: [experiments/README.md](../../experiments/README.md).
Firefox/Safari этой проверкой не покрывались.
