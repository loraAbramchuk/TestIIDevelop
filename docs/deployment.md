# Установка и обслуживание (этапы 11–12)

Поддерживается один Ubuntu 24.04 LTS сервер, PostgreSQL 17 и локальные POSIX
volumes. Публичный выпуск выполняется отдельно. Результаты и границы проверки:
[этап 11](verification/stage-11.md) и [этап 12](verification/stage-12.md).

Версия 0.2.0 добавляет миграцию 0012, подтверждение email и восстановление
пароля. До открытия регистрации настройте SMTP и канонический HTTPS origin
по [инструкции](email.md). Провайдер пока не выбран: тестовая отправка проверена
на изолированном SMTP. Без настроек регистрация отвечает 503 до создания аккаунта;
режим регистрации только по приглашениям не вводится. Существующий `.env` не
переписывается: недостающий ключ добавляет явная команда `init_env.py --prepare-mail`.
Перед обновлением подготовьте SMTP и согласованную копию, затем используйте
штатный `update`. Старые аккаунты после миграции должны подтвердить email перед
действиями с контентом; пароли, каналы и сессии сохраняются.

## Установка одной командой

Нужны root/sudo, исходящий HTTPS, свободное место для образов, media и временного
снимка, домен с A/AAAA на сервер и входящие TCP 80/443. Удалите неверную AAAA,
если IPv6 не обслуживается. Другой веб-сервер не должен занимать эти порты.
Откройте SSH и 80/443 в облачном и системном firewall до установки. Установщик
не меняет правила firewall. Не публикуйте PostgreSQL или порт FastAPI.

После отправки и ревью этой ветки замените `REVIEWED_COMMIT` на полный SHA
содержащего установщик коммита, а домен/email — на свои значения:

```bash
curl -fsSL https://raw.githubusercontent.com/loraAbramchuk/TestIIDevelop/REVIEWED_COMMIT/scripts/install.sh | sudo bash -s -- --ref REVIEWED_COMMIT --domain video.example.com --email ops@example.com
```

Установщик устанавливает Docker Engine/Compose из Ubuntu APT, Python, age, SSH-клиент,
Certbot и tar; получает указанный ref в `/opt/video-platform`, создаёт приватный `.env`
с независимым случайным паролем БД, получает сертификат через HTTP-01, собирает
образы, применяет миграции, запускает сервисы и проверяет диагностику. Compose
должен быть >= 2.24.4 (нужен `!override`). Скрипт выполняется с root и устанавливает
системные пакеты и units. Сначала просмотрите код выбранной версии.

Для локального HTTP без домена: те же параметры без `--domain/--email`;
слушается только `127.0.0.1:8080`. HTTPS-конфигурация слушает 80/443 снаружи.
`--prefix`, `--repository`, `--ref`, `--project`, `--http-port` меняют установку.
Один стандартный wrapper и набор systemd units обслуживают одну установку.
Для нескольких проектов используйте отдельные пути, порты, APP_IMAGE/WEB_IMAGE
и собственные units с явными `--root/--project/--env-file`.

Повторная **та же** команда сохраняет `.env`, volumes и секреты. При другой
версии на существующей установке скрипт откажет: используйте `update`, который
сначала делает согласованный backup. Нельзя запускать установщик поверх каталога
с локальными изменениями. После добавления backup-настроек повторный запуск
установщика с тем же ref включит таймер.

Первый администратор создаётся интерактивно, без пароля в аргументах:

```bash
cd /opt/video-platform
sudo docker compose exec app python -m app.cli create-admin --email admin@example.com --name Администратор
sudo video-platform status
```

Команду CLI уточняйте через `python -m app.cli --help`; стандартных аккаунтов нет.
Swagger доступен по `https://video.example.com/docs`.

## HTTPS и продление

`SITE_DOMAIN` и `ACME_EMAIL` задаются в `.env`. CLI `tls` использует временный
HTTP-only Nginx с ACME webroot, затем `start` включает HTTPS. Обычный HTTP
перенаправляется на канонический домен, неизвестный Host отклоняется. TLS 1.2/1.3,
HSTS и Secure `__Host-` session cookie включены production overlay независимо от
локального AUTH_COOKIE_SECURE. Media остаются за ACL/internal Nginx.

```bash
sudo video-platform renew
sudo systemctl list-timers 'video-platform-*'
sudo journalctl -u video-platform-renew.service
```

Повторный установщик сохраняет действующий сертификат; истёкший или истекающий
в ближайшие сутки переводит в получение/обновление через Certbot. Работающий
production Nginx продолжает обслуживать HTTPS и HTTP-01, замена на временный
HTTP gateway ему не требуется. При неудачном переходе с локального HTTP прежний
gateway восстанавливается.

Certbot проверяется дважды в сутки; после успешной проверки Nginx проверяет
конфигурацию и перечитывает сертификат. Port 80 должен оставаться доступен для
HTTP-01. Срок сертификата меньше 14 дней делает `status` degraded. Восстановление
сохраняет TLS-ключи и ACME account в зашифрованной копии. Если сертификат уже
истёк и веб-сервер остановлен, обеспечьте доступность HTTP-01 и выполните `tls`,
затем `start`. Для работающего HTTPS-сервера можно выполнить `renew`.

## Внешние зашифрованные копии

Создайте age identity **на отдельной доверенной машине**:

```bash
age-keygen -o recovery-key.txt
age-keygen -y recovery-key.txt
```

Сохраните identity отдельно от сервера и его backup-каталога; на сервер передаётся
только публичный recipient `age1...`. Потеря identity означает невозможность
расшифровать копию. Сохраните отдельно проверенный SHA исходников/образ релиза:
архив содержит image ID и Git revision, но сами исходники/образы в него не входят.

Создайте SSH-аккаунт на другом сервере и отдельный каталог, ограничьте доступ.
На сервере приложения установите SSH identity 0600 и known_hosts с **проверенным
по независимому каналу** fingerprint. Код не доверяет первому соединению и
не отключает проверку host key. В `.env` (не shell `source`):

```dotenv
BACKUP_RECIPIENT=age1_REPLACE_WITH_REAL_RECIPIENT
BACKUP_SSH_TARGET=backup@backup.example.com
BACKUP_SSH_PATH=/srv/backups/video-platform
BACKUP_SSH_IDENTITY=/root/.ssh/video-backup
BACKUP_SSH_KNOWN_HOSTS=/root/.ssh/known_hosts
BACKUP_SSH_PORT=22
```

SSH использует явные параметры CLI и `-F /dev/null`, поэтому пользовательские
Host/ProxyJump из ssh_config не применяются. SSH-пользователь должен иметь возможность mkdir/cat/sha256sum/mv, чтения и записи
в этот каталог. Удаление и политика хранения на внешнем хосте — задача оператора;
не предоставляйте серверу приложения доступ к age identity.

```bash
sudo video-platform backup
sudo systemctl list-timers video-platform-backup.timer
sudo journalctl -u video-platform-backup.service
```

Ежедневный таймер включается установщиком только при полном наборе recipient и
SSH destination. До этого автоматических внешних копий **нет**.

На время снимка останавливаются Nginx, app, worker и maintenance: незавершённые
операции завершаются/прерываются с обычной recovery-политикой. Пока writers стоят,
создаются pg_dump и media tar; это согласованный снимок. Есть окно недоступности,
его длительность зависит от размера media/БД и шифрования. На сервере нужно место
под несжатый media snapshot, dump и зашифрованный архив. Перед остановкой
сервисов CLI оценивает логический размер media и tar-заголовков, размер БД/TLS,
совместное хранение plaintext snapshot и encrypted output с запасом на формат.
Оценка консервативная. Во время dump, копирования, сжатия/шифрования и распаковки
свободное место проверяется порциями до 1 МиБ. При достижении резерва дочерние
процессы завершаются, временные файлы удаляются, исходные сервисы backup возобновляются.
`BACKUP_MIN_FREE_BYTES` по умолчанию 2 ГиБ; фактический резерв — максимум этой
настройки и `MEDIA_MIN_FREE_BYTES`. Не уменьшайте его без оценки PostgreSQL/WAL
и других процессов. Это контроль операции, а не эксклюзивная резервация диска:
другие приложения также могут расходовать место.

PostgreSQL остаётся запущен;
не допускайте сторонних SQL-записей во время backup.

В архив входят БД, исходники/производные media, `.env`, TLS/ACME и manifest с SHA-256,
ревизией схемы и образом. Временные незашифрованные файлы находятся в каталоге
0700 и удаляются в finally; пароль `.env` не выводится. Архив шифруется age,
передаётся SSH во временный файл, хеш проверяется на принимающей стороне, затем
выполняется атомарный rename. После копирования запускаются только ранее работавшие
сервисы: намеренно остановленный worker не включается. Ошибка копирования также
возобновляет исходные сервисы. При ошибке SSH локальный зашифрованный файл остаётся;
для повтора используйте `video-platform ship /path/copy.tar.age`.

По умолчанию локально остаётся 7 подтверждённых внешних копий, внешний каталог
автоматически не очищается. `BACKUP_KEEP_LOCAL` меняет локальный retention.
`BACKUP_DIR` должен быть 0700. `backup --local-only --recipient age1...` допустим
для изолированных проверок, но не заменяет внешнюю копию. Конкурентные операции
одного проекта блокируются файловой блокировкой. SIGTERM возобновляет writers;
после SIGKILL/падения хоста проверьте `.local/operations/PROJECT/backups/.snapshot-*`:
там могут оставаться временные незашифрованные снимки, доступные только root.

## Восстановление

Используйте новый хост/пустой проект и совместимый код сохранённого релиза.
Доверяйте только копии с SHA-256 из независимо сохранённого отчёта: age шифрует
данные получателю, но не удостоверяет отправителя.
Установите Docker/Compose, Python и age; получите **проверенный код** и соберите
образы `docker compose build app web`, используя отдельную временную build-env,
если для Compose нужен пароль. Не выполняйте `start`/установку приложения в целевом
проекте: restore откажется перезаписывать любой существующий env, контейнер или
volume. Код и зависимости должны быть доступны независимо от потерянного сервера.

Скачайте зашифрованный архив с внешнего хоста, проверьте его SHA-256 по сохранённому
отчёту. Временно передайте recovery identity на доверенный хост восстановления:

```bash
sudo python3 scripts/ops.py --root /opt/video-platform --project video-restored --env-file /opt/video-platform/restored.env --production restore /safe/copy.tar.age --identity /safe/recovery-key.txt
sudo python3 scripts/ops.py --root /opt/video-platform --project video-restored --env-file /opt/video-platform/restored.env --production status
```

Для HTTP-копии опустите `--production`. В тестах можно указать `--http-port`,
`--https-port`, `--public-http-port`. Проверяются формат, хеши, версия PostgreSQL,
известная ревизия Alembic и безопасные пути архива **до создания БД/env**.
Расшифровка и извлечение проверяют место и резерв; до импорта проверяется место
в Docker volumes, во время импорта БД/media выполняются повторные проверки.
Новые архивы содержат исходный размер БД; для старых используется консервативная
оценка по dump плюс контроль при записи. Часть места требуется также под новые
контейнеры и восстановление ожидавших заданий.
БД восстанавливается одной транзакцией; media — в новый volume с исходными правами
владельца. TLS переносится в новый project directory. В `renewal/*.conf` переносятся
`archive_dir`, cert/key/chain/fullchain и HTTP-01 webroot/map; ACME account,
сервер, имя сертификата и относительные live→archive symlinks сохраняются.
После переноса проверьте `certbot certificates` с новым `--config-dir`, затем
на целевом домене выполните `certbot renew --dry-run` с теми же config/work/log dirs. Схема догоняется до head,
включаются worker/recovery, диагностика проверяется до открытия Nginx.

Перед переключением DNS/трафика проверьте сессии и роли, приватный доступ и его
отзыв, скрытые видео, MP4/превью/Range, нативное воспроизведение и очередь. Затем
создайте wrapper/units для нового project/env; прежний wrapper автоматически не
перенастраивается. Проверьте SSH credential/known_hosts на новом хосте и включите
backup/renew timers. Ключ расшифрования удалите с прикладного хоста после проверки.
При частичном сбое restore останавливает и прикладные writers, и новую БД,
чтобы pg_restore не продолжал запись после отключения клиента. Данные сохраняются
для анализа; БД можно отдельно запустить для диагностики.
Повторный restore выполняется в другом **пустом** проекте, не поверх частичного.

## Обновление и сбой релиза

```bash
sudo video-platform update REVIEWED_COMMIT
```

Нужны чистый checkout и рабочие внешние копии. Команда получает ref, сохраняет
старые образы, делает encrypted off-site snapshot и оставляет writers остановленными,
переключает код, собирает, применяет миграции и проверяет сервисы. После успешного
старта запишите SHA/образ и `status`. Не применяйте `docker compose down --volumes`
для обновления и не меняйте POSTGRES_PASSWORD у уже созданного volume вручную.

Ошибка до начала миграций возвращает прежний checkout/образы и ранее работавшие
сервисы. После возможного начала миграций автоматического downgrade нет: старая
версия приложения может быть несовместима с новой схемой или политикой доступа.
CLI указывает snapshot и прежний SHA, оставляя writers остановленными. Исправьте
релиз вперёд либо восстановите копию с прежним кодом в **пустом** окружении и
проверьте доступы перед переключением. Восстановление старой копии теряет записи,
созданные после её времени. Не выполняйте Alembic downgrade без отдельной оценки
каждой миграции и совместимости старого кода. Для PostgreSQL major upgrade нужен
отдельный проверенный план; этот CLI рассчитан на PostgreSQL 17.

## Наблюдение

Systemd unit `video-platform.service` — boot-start oneshot; для остановки стека
используйте `docker compose ... stop` с теми же env/project/production overlays.
Остановка этого oneshot unit сама по себе не останавливает контейнеры.

`video-platform status` возвращает JSON и exit 0 для ok / 1 для degraded:
контейнеры, readiness/diagnostics, свободный диск и резерв, очередь по состояниям,
число живых worker, uploads, последние HTTP 4xx/5xx и срок TLS. HTTP-ошибки —
выборка последних 300 строк Nginx, не полная статистика. Агрегаты не содержат
пользователей, private file paths или SQL. Объём свободного места включает общий
файловый раздел; отдельно наблюдайте Docker/backup-раздел, inode и внешнее хранилище.

`/health/live` — процесс; `/health/ready` — просмотр (БД + чтение media);
`/health/diagnostics` — приём/обработка. Diagnostics HTTP 200 требует проверки
JSON status. Остановка worker даёт degraded, но сохраняет просмотр/Range и приём
заданий до лимита очереди. Алерты на diagnostics, диск, 5xx, устаревшую копию и
срок TLS настройте во внешнем мониторинге. `status` показывает последнее успешное
копирование, но сам не проверяет внешний файл и не заменяет периодический restore.

Nginx пишет JSON без query string, Cookie и Authorization; Uvicorn access log
отключён. Error log Nginx ограничен crit, чтобы ошибки upstream не записывали
полные приватные URL/query; диагностика опирается на статусы и локальные сервисные
логи. Исходный URI видео UUID остаётся в access log, внутренний storage key не пишется: ограничьте доступ и retention.
Ротация Docker logs ограничивает рост; устанавливайте системную политику хранения
journald/Certbot/SSH и резервных копий. Не публикуйте `.env` или полные compose config.
