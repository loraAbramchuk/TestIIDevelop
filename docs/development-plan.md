# План разработки по шагам и модулям

Статус: план оставшейся реализации MVP. Выполненное отмечено отдельно;
перечисление задачи не означает, что она реализована. Даты не назначены:
длительность обработки и вместимость сервера сначала нужно измерить.

Основание: [требования](requirements.md), [архитектура](architecture.md),
[сценарии приёмки](acceptance.md). При изменении требований обновляются эти документы.

## Готовая основа — этап 0

- [x] FastAPI, PostgreSQL, SQLAlchemy, Alembic, Docker Compose, Nginx.
- [x] Swagger, главная с пустым состоянием, проверки HTTP/БД/хранилища.
- [x] Регистрация, вход, выход, текущий пользователь и формы.
- [x] Argon2id, серверные сессии, CSRF, ограничения попыток.
- [x] Роли user/moderator/admin, зависимость проверки роли, CLI создания администратора.
- [x] CI-конфигурация; локально выполнены 27 тестов и браузерная проверка авторизации.

Видео, предметные права на видео, worker, каналы, социальные функции, модерация,
панель администратора и установщик чистой Ubuntu пока не реализованы.

## Этап 1. Зафиксировать контракты видео и выбрать очередь

**Задачи**

- [ ] Описать запросы и ответы создания видео, передачи файла, статуса, просмотра и grants.
- [ ] Зафиксировать базовый профиль: MP4, H.264 8-bit yuv420p, AAC-LC при наличии звука; проверить образцы в целевых браузерах.
- [ ] Сохранить начальное ограничение 1 GiB/файл; определить настраиваемые квоты, запас диска, параллелизм и таймауты.
- [ ] Проверить готовую PostgreSQL-очередь, например Procrastinate, на совместимость и согласованную запись видео/задания. Проверить повтор после аварии worker.
- [ ] Записать решение по очереди. Если библиотека не подходит, обосновать небольшую собственную реализацию и обязательные проверки отказов; две очереди одновременно не создавать.
- [ ] Разделить готовность HTTP, доступность storage и состояние обработки. Остановка worker не должна останавливать просмотр готовых видео.
- [ ] Различать возможность читать готовые файлы и принимать новые записи; при нехватке места блокировать загрузки, сохраняя просмотр, пока доступны БД и чтение.

**Результат:** согласованные контракты и проверенный технический выбор очереди.
Новые рабочие endpoints и поддержка форматов ещё не объявляются реализованными.
Поддержка несовместимых входных файлов через перекодирование — отдельный подэтап
после оценки ресурсов, с одним выходным MP4. HLS и несколько качеств отложены.

## Этап 2. Домен видео и единые права доступа

**Модули:** videos, access, auth.

- [ ] Добавить модели и миграции videos и video_grants; создать ограничения и индексы.
- [ ] Разделить видимость, состояние обработки, модерацию и удаление.
- [ ] Реализовать создание/редактирование своих метаданных, просмотр статуса своих загрузок.
- [ ] Реализовать выдачу доступа существующему пользователю и отзыв разрешения владельцем.
- [ ] Сделать общую политику просмотра для одного объекта и SQL-фильтр для списков.
- [ ] Проверять владение отдельно от роли; привилегированная роль не открывает приватное содержимое автоматически.

**Приёмка:** матрица гость/владелец/приглашённый/посторонний/модератор/администратор.
Нельзя менять чужое видео, подделать владельца, получить приватные метаданные
или сохранить доступ после отзыва. Подготовка тестовых статусов не означает,
что рабочая обработка и воспроизведение уже существуют.

## Этап 3. Постоянное хранение и загрузка

**Модули:** storage, videos, web.

- [ ] Реализовать локальное хранилище с серверными ключами и уникальными временными файлами.
- [ ] Добавить потоковую бинарную передачу после создания метаданных; не читать весь файл в RAM.
- [ ] Проверять авторизацию/CSRF до тела, реальный размер, квоту и число одновременных загрузок.
- [ ] Атомарно резервировать место по учётным квотам; отдельно проверять свободное место и резерв для обработки.
- [ ] Добавить аренду передачи, её продление и запрет второго писателя. Потерявший аренду писатель прекращает работу.
- [ ] Согласовать лимиты/таймауты Nginx и API, отключить buffering для бинарной передачи.
- [ ] Закрыть файл, завершить запись и записать задание выбранным на этапе 1 способом.
- [ ] Добавить очистку незавершённых файлов с проверкой активных аренд.
- [ ] Сделать экран `/upload`: файл, название, описание, private по умолчанию, прогресс и отдельный статус обработки.

**Приёмка:** превышение размера, ложный Content-Length, обрыв, медленная передача,
параллельные запросы, исчерпание квоты и места на диске. Файлы не перезаписывают
друг друга; никакой прямой публичной ссылки на хранилище нет.
Возобновление с позиции обрыва в MVP не обещается: повтор начинает передачу заново.

## Этап 4. Worker и обработка видео

**Модули:** jobs, processing, storage.

- [ ] Подключить отдельный worker в Compose и выбранную PostgreSQL-очередь.
- [ ] Проверять фактические контейнер/кодеки/параметры через ffprobe; расширение файла не считается проверкой.
- [ ] Создавать превью, извлекать длительность и размеры кадра.
- [ ] Подготавливать совместимый MP4 с faststart; на базовом этапе без перекодирования неподдерживаемых кодеков.
- [ ] Ограничить CPU, память, время, число одновременно обрабатываемых файлов и доступные протоколы FFmpeg.
- [ ] Публиковать результаты только завершённой актуальной попытки и только для неудалённого видео.
- [ ] Реализовать ограниченные повторы временных ошибок и безопасные сообщения постоянных ошибок.
- [ ] Добавить heartbeat и наблюдение за очередью; очистка не затрагивает активные задания.

**Приёмка:** авария в середине задания, повторное получение задания, старый worker
после истечения аренды, ошибка FFmpeg, перезапуск и удаление во время обработки.
Успешный результат публикуется согласованно; устаревший worker его не заменяет.

## Этап 5. Защищённое воспроизведение и первый сквозной сценарий

**Модули:** videos, access, storage, web, Nginx.

- [ ] Добавить stream и thumbnail endpoints с общей проверкой доступа.
- [ ] Подключить внутренний location Nginx и X-Accel-Redirect; mount файлов у Nginx только для чтения.
- [ ] Проверить GET/HEAD, Content-Type, Range, 206/416, перемотку и длительность.
- [ ] Исключить общедоступные пути и кэширование, позволяющее обойти смену приватности.
- [ ] Сделать `/watch/{id}` с плеером, названием и описанием, а также управление своей загрузкой и grants.
- [ ] Сделать удаление: немедленный запрет просмотра, отмена обработки, устойчивое задание очистки файлов.

**Приёмка:** пользователь загружает видео, видит превью и смотрит с перемоткой;
выдаёт доступ другому аккаунту и отзывает его. Посторонний не получает файл,
диапазон, превью или метаданные даже по прямому адресу. Перезапуск сохраняет
готовые ролики. Остановка worker не ломает просмотр ранее готовых видео.

**Контрольная точка M1: работает сердце системы.** До этого не начинаем
массовое добавление социальных функций. Контур остаётся закрытым для разработки.

## Этап 6. Главная, поиск, каналы и подписки

**Модули:** catalog, channels, videos, web.

- [ ] Создать channels, subscriptions и миграцию каналов существующим пользователям.
- [ ] Создавать канал нового пользователя транзакционно вместе с регистрацией.
- [ ] Реализовать главную с публичными готовыми видео, превью, автором и пагинацией.
- [ ] Реализовать поиск по части названия, экранирование спецсимволов запроса и пагинацию.
- [ ] Сделать канал с доступными видео, описанием и редактированием владельцем.
- [ ] Добавить подписку/отмену без дублей и запрет подписки на себя.

**Приёмка:** приватные, скрытые, удалённые и неготовые видео не раскрываются в
публичной выдаче. Канал учитывает права посетителя. Пустые результаты и состояния
ошибок понятны; подписка не даёт доступ к приватным роликам.

## Этап 7. Лайки и комментарии

**Модули:** interactions, videos, web.

- [ ] Добавить таблицы и API лайка/снятия лайка с уникальностью user/video.
- [ ] Добавить текстовые комментарии, пагинацию и удаление своего комментария.
- [ ] Применить политику просмотра к чтению и записи взаимодействий.
- [ ] Проверять CSRF, длину текста, частоту записи и безопасное отображение.
- [ ] Подключить действия и счётчики на страницу просмотра.

**Приёмка:** параллельные лайки не дублируются, чужой комментарий нельзя удалить,
HTML отображается как текст. После потери доступа нельзя читать комментарии и
счётчики либо добавлять новые взаимодействия.

## Этап 8. Плейлисты

**Модули:** playlists, channels, videos, web.

- [ ] Добавить плейлисты, элементы и ограничения уникальности.
- [ ] Создавать, переименовывать и удалять свои плейлисты.
- [ ] Добавлять/удалять видео, менять порядок транзакционно.
- [ ] Подключить плейлисты на канал и отдельную страницу плейлиста.

при следующем запросе, даже если видео добавили в плейлист раньше.

- [ ] Сделать отправку жалобы на доступное видео и очередь рассмотрения с пагинацией.
- [ ] Реализовать скрытие и восстановление с обязательной причиной и атомарной записью аудита.
- [ ] Показать владельцу причину скрытия в управлении загрузкой.

## Правило завершения каждого этапа

У этапа должны быть миграции при изменении БД, рабочий API с актуальным Swagger,
соответствующий экран, проверки прав и ошибок, целевые тесты и обновлённые
инструкции запуска. Проверки выбираются по изменению; полный набор не повторяют
без причины на каждом промежуточном редактировании.

Каждую законченную часть удобно оформлять небольшим проверенным коммитом.
Создание коммита, отправка на GitHub и публикация облачной среды — разные операции;
публикация среды сама по себе не отправляет код в репозиторий.

Ближайшая работа: **этап 1, затем этап 2 — контракты и очередь, модели видео,
владение и приватные разрешения**. Массовый перенос готовой авторизации по
каталогам не должен задерживать первый сквозной сценарий видео.
