# Администрирование пользователей: этап 10

Все операции только admin; guest — 401, user/moderator — 403.
Страницы `/admin/users` и `/admin/audit` перенаправляют гостя на вход с next,
обычному пользователю/модератору возвращают HTML 403. Данные private/no-store,
Vary: Cookie. Файлы и grants не открываются по роли автоматически.

| Метод | Endpoint | Ответ |
| --- | --- | --- |
| GET | `/api/admin/users?q=...&role=all&limit=20&cursor=...` | 200 UserPage |
| GET | `/api/admin/users/{user_id}` | 200 UserProfile |
| PATCH | `/api/admin/users/{user_id}/role` | 200 RoleChangeResult |
| GET | `/api/admin/audit?user_id=...&limit=20&cursor=...` | 200 AuditPage |

AdminUser: id, email, display_name, role, created_at. Без password_hash, токенов,
сессий или файловых ключей. UserProfile: user=AdminUser, admin_count.
UserPage: items, admin_count и nullable next_cursor. Поиск q до 200 символов,
trim, без учёта регистра по подстроке имени/email; `%`, `_`, `/` и `\` буквальны.
NUL/невалидный Unicode — 400 invalid_query. Фильтр role=all/user/moderator/admin,
по умолчанию all; неизвестное значение — 422. Сортировка created_at/id по убыванию,
limit 1–100 (20), cursor до 1024 символов с контекстом пользователя/q/role.
Неверный контекст/повреждение — 400 invalid_cursor; курсор не фиксирует снимок БД.

PATCH требует сессии и X-CSRF-Token. Тело:

```json
{"role":"moderator","reason":"Рассмотрена заявка","expected_role":"user"}
```

role — user/moderator/admin, reason — 1–2000 символов после trim. expected_role
необязателен (null равен отсутствию), используется для проверки старой формы.
Неизвестные поля, null role/reason, пустая причина, NUL/непарный суррогат — 422.
Если текущая роль отличается от expected_role и требует изменения — 409
role_conflict. Если желаемая роль уже назначена — 200 changed=false без события
или замены причины. Последнего администратора нельзя понизить: 409 last_admin.
Неизвестный user_id — 404 user_not_found. Назначение и AuditEvent атомарны;
исполнитель проверяется заново под блокировкой после ожидания общего mutex.

RoleChangeResult расширяет UserProfile полями changed и actor_role.
changed=true означает новую запись user.role_changed; false — отсутствие перехода.
actor_role может стать user/moderator при самопонижении. Текущая сессия остаётся
действующей, административные операции с новым запросом уже запрещены.
ADMIN_WRITE_LIMIT_PER_MINUTE=30 — персональный лимит, превышение 429 с Retry-After.
Повторные и неуспешные предметные операции также расходуют лимит.

AuditPage: items и nullable next_cursor. Только события user.role_changed,
необязательный user_id фильтрует UUID цели. Поля: id, actor_id, object_type=user,
object_id, action, reason, created_at, details={previous_role, role}.
Сортировка/пагинация как у списка пользователей; курсор привязан к admin и фильтру.
История не каскадирует UUID при удалении объектов, API изменения/удаления нет.
Журнал модерации не возвращает историю назначения ролей даже модератору.

Полный актуальный Swagger — `/docs`; экспорт с четырьмя операциями включён в
[video.openapi.json](video.openapi.json). Bootstrap администратора — отдельный
CLI, существующие аккаунты он не меняет. Миграция 0011 создаёт только два индекса,
не меняя текущие роли и прежнюю историю.


## Восстановление интерфейса

Неверный или отсутствующий CSRF возвращает 403 с code=csrf_invalid.
Это не подтверждение утраты роли. Панель перепроверяет `/api/auth/me` и текущую
карточку; при прежнем admin сохраняет форму и предлагает повторить действие
вручную с новым токеном. При неподтверждённой сессии запись заблокирована,
но чтение можно повторить. Другая учётная запись или фактически потерянная
роль закрывают панель; административный PATCH автоматически не повторяется.

Общий браузерный JSON helper ограничивает каждый HTTP-запрос 15 секундами,
включая чтение тела после заголовков. CSRF preflight и сама запись имеют
собственные границы. request_timeout — локальный код ошибки JavaScript,
не новый HTTP-ответ API. Клиентский abort не гарантирует отмену серверной
транзакции; результат может быть записан после таймаута. Интерфейс сохраняет
причину, читает текущее состояние и не выдаёт подтверждение аудита по одному GET.
Неуспешное чтение отключает новую запись до ручного обновления.

Совпадение выбранной роли с серверной снимает признак несохранённого выбора:
последующие обновления отражают новые назначения. Если выбор всё ещё отличается
от текущей роли, он сохраняется вместе с текстом причины.
