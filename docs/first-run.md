# Первый запуск и демонстрационные данные

Локальная проверка не требует внешнего SMTP. Из checkout с Docker/Compose
и Python 3 выполните одну команду:

```bash
bash scripts/start.sh
```

Будут созданы приватный `.env` со случайными ключами, БД и схема; запустятся
app, worker, maintenance, Nginx и Mailpit. Существующие пароли БД, ключи,
настройки и данные сохраняются. При отсутствующем signing secret старой
локальной установки он добавляется атомарно; повтор сохраняет его.

1. Откройте http://localhost:8080/register и создайте аккаунт.
2. После регистрации сессия уже активна. Выйти и войти можно до подтверждения.
3. Откройте http://localhost:8025 — ссылка «тестовый почтовый ящик» есть на
   страницах сайта. Это Mailpit, который принимает локальные письма без пересылки.
4. В письме перейдите по ссылке, нажмите «Подтвердить email». После этого
   доступны загрузка и другие действия с контентом.
5. Для проверки восстановления выйдите, нажмите «Забыли пароль?» и получите
   второе письмо в том же ящике. Новый пароль отзывает все прежние сессии.

`HTTP_PORT`, `MAILPIT_HTTP_PORT` и `MAILPIT_SMTP_PORT` меняют порты. При изменении
HTTP_PORT Compose по умолчанию строит соответствующий PUBLIC_BASE_URL.
Вручную заданный PUBLIC_BASE_URL сохраняет приоритет. Mailpit доступен только
через loopback-порты; его UI содержит ссылки доступа, не публикуйте их наружу.
При пересоздании Mailpit письма теряются, новое можно запросить через интерфейс.

`MAIL_BACKEND=auto` сохраняет приоритет заданного `SMTP_HOST`. Без него локальный
HTTP использует Mailpit. Для своего провайдера укажите `MAIL_BACKEND=smtp` и
остальные [SMTP-настройки](email.md). Production overlay принудительно использует
SMTP для app/worker/maintenance/migrate и не запускает Mailpit по умолчанию.
Недостающие production-настройки обнаруживаются launcher до остановки сервисов.

## Seed

После готовности приложения и worker выполните:

```bash
docker compose exec app python -m app.seed --demo
```

Для Python на хосте: `uv run --locked python scripts/seed.py --demo`.
По умолчанию seed обращается к app на http://127.0.0.1:8000; при другом порте
задайте `--base-url http://127.0.0.1:PORT`. Он принимает только loopback HTTP
и локальную Mailpit-конфигурацию. Из публичного HTTPS/SMTP seed откажется
работать до создания данных. Автоматически при старте он не выполняется.

| Email | Роль | Начальный пароль |
| --- | --- | --- |
| creator@demo.example.com | пользователь, автор | DemoVideo2026! |
| viewer@demo.example.com | пользователь, получатель приватного доступа | DemoVideo2026! |
| moderator@demo.example.com | модератор | DemoVideo2026! |
| admin@demo.example.com | администратор | DemoVideo2026! |

Только эти явно созданные demo-аккаунты сразу подтверждены доверенным seed.
Публичная регистрация по-прежнему создаёт только неподтверждённого пользователя.
Постоянных default-аккаунтов при обычном запуске нет.

Скрипт создаёт четыре канала, три публичных и один приватный ролик с тестовыми
кадрами и звуком, превью, плейлист с тремя элементами, разрешение для viewer,
подписку, лайк, комментарий и открытую учебную жалобу. Можно войти всеми ролями,
увидеть наполненную ленту, проверить приватность, модерацию и управление ролями.
Гость видит только три публичных видео и доступную ему часть плейлиста.

Файлы действительно генерируются FFmpeg, отправляются через бинарный upload API
и проходят штатную очередь/worker до ready. Нет фиктивных ready-записей без MP4.
Seed требует здоровой диагностики и worker; ожидает обработку до 90 секунд на
ролик (`--timeout` — 1–600 секунд). Для API создаётся короткая служебная сессия,
которая удаляется в finally; существующие пользовательские сессии не меняются.

Стабильные UUID и advisory lock исключают параллельное наполнение и дубли.
Повторный запуск сохраняет существующие пароли, роли, названия, приватность и
порядок уже созданного плейлиста, не поднимает удалённые ролики. Удалённые demo
социальные записи могут быть добавлены снова: это команда наполнения примеров.
При совпадении demo-email с чужим аккаунтом seed отказывается от создания
учётных записей без повышения роли или замены пароля. Он не выполняет общий
truncate/drop и не удаляет пользовательские файлы.

## Проверка исправления

Воспроизводимый изолированный прогон:

```bash
uv run --locked python experiments/first_run_probe.py /tmp/first-run-new-check
```

Нужны Docker, Node/Playwright, Chromium, FFmpeg и зависимости проекта; новый
каталог результатов и свободные порты 15434/8014/8099/1026/1027/8026.
Используются собственные БД/volume, Nginx и Mailpit; основной стек не меняется.
Подробные условия и результаты записаны в [отчёте](verification/first-run.md).
