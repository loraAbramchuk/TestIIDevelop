# Требования к видеоплатформе

Статус: рабочая спецификация для первой версии. Раздел «Принятые технические предположения» содержит предложенные решения, которые можно уточнять по ходу разработки.

## Подтверждённые требования

- Backend: Python и FastAPI.
- База данных: PostgreSQL.
- Документация API: Swagger по адресу `/docs`.
- Простой веб-интерфейс.
- Развёртывание на чистой Ubuntu одной командой.
- Основная функция: загрузка, постоянное хранение и раздача видео.
- Роли: пользователь, модератор, администратор.
- Приватное видео доступно только владельцу и пользователям, которым он разрешил доступ.
- Главная: лента видео с превью.
- Просмотр: плеер, лайки, комментарии.
- Канал: видео и плейлисты автора, подписка.
- Поиск по названию видео.
- Загрузка: выбор файла, прогресс и метаданные.
- Вход и регистрация.
- Модерация: жалобы и скрытие видео.

## Принятые технические предположения

Эти решения конкретизируют требования для MVP. Инфраструктура и авторизация уже
реализованы; состояние остальных компонентов и технические решения описаны в
[архитектуре](architecture.md). Список ниже не является отчётом о готовности функций.

- Один сервер Ubuntu 24.04 LTS, Docker Compose, Nginx, FastAPI, PostgreSQL и отдельный процесс обработки видео.
- Простой фронт: серверные шаблоны Jinja2, HTML/CSS и JavaScript без отдельной SPA.
- SQLAlchemy и Alembic для данных и миграций.
- Файлы и превью хранятся в постоянном volume вне каталога исходного кода, в БД находятся метаданные и непрозрачные ключи файлов. Видео не хранится в PostgreSQL.
- Начальная поддержка: MP4 с H.264/AAC, проверка содержимого через ffprobe, превью через FFmpeg. Файлы с другими контейнерами или кодеками отклоняются с объяснением. Перекодирование произвольных форматов, несколько качеств и HLS — следующий этап.
- Лимит файла настраивается; начальное значение — 1 ГиБ. Приложение и Nginx используют согласованные ограничения.
- Публичные видео можно смотреть без входа. Для остальных действий нужна учётная запись. Авторизация должна появиться до публикации загрузки, удаления и приватных видео в интернете.
- Регистрация создаёт только роль пользователя. Первого администратора создают отдельной административной командой без пароля по умолчанию; публичная регистрация не принимает роль.
- Сессии используют HttpOnly cookies, защиту от CSRF и безопасное хеширование паролей. Для публичного сервера требуется HTTPS.
- Доступ к приватному видео выдаётся существующей учётной записи по точному идентификатору; приглашения по ссылке и доступ анонимным посетителям не входят в MVP.
- Прогресс загрузки показывает передачу файла. Проверка и создание превью показываются отдельным статусом обработки.

На этапе 1 уточнены [контракт API](api/video-contract.md),
[профиль и настраиваемые лимиты](video-policy.md), а также
[выбор очереди](decisions/0001-postgresql-queue.md). Это спецификация следующих
этапов, а не утверждение о готовой загрузке или обработке.

## Роли и права

Владелец — отношение пользователя к конкретному видео, каналу или плейлисту, а не отдельная системная роль. Модератор и администратор также могут пользоваться обычными функциями пользователя.

| Действие | Гость | Пользователь | Модератор | Администратор |
| --- | --- | --- | --- | --- |
| Смотреть доступные публичные видео, каналы, поиск | Да | Да | Да | Да |
| Смотреть приватное видео | Нет | Владелец или получатель доступа | По тем же правилам | По тем же правилам |
| Загружать видео, управлять своим каналом | Нет | Да | Да | Да |
| Менять метаданные, приватность, удалять видео | Нет | Только свои | Только свои | Только свои |
| Выдавать и отзывать доступ к приватному видео | Нет | Только свои | Только свои | Только свои |
| Ставить лайк, комментировать, подавать жалобу | Нет | Для доступного видео | Для доступного видео | Для доступного видео |
| Подписываться, создавать свои плейлисты | Нет | Да | Да | Да |
| Рассматривать жалобы, скрывать и восстанавливать видео | Нет | Нет | Да | Да |
| Назначать роли | Нет | Нет | Нет | Да |

Роль модератора или администратора сама по себе не даёт права смотреть приватные файлы. В очереди жалоб доступны необходимые сведения о жалобе и объекте; воспроизведение подчиняется обычной проверке доступа. Расширение прав просмотра требует отдельного решения.

## Видимость и жизненный цикл видео

Независимые поля состояния:

- Видимость: `public`, `private`.
- Обработка: `uploading`, `processing`, `ready`, `failed`.
- Модерация: `visible`, `hidden`.

Просмотр разрешён только для готового, не скрытого видео с подходящими правами доступа. Скрытое видео недоступно для просмотра всем ролям; владелец видит статус и причину в управлении своими загрузками. Модератор может восстановить его после решения по жалобе.

Проверка доступа обязательна для страницы видео, API, содержимого файла и Range-запросов, превью, комментариев и счётчиков. Угаданный URL или ключ файла не даёт доступа. Nginx раздаёт файлы только через внутренний маршрут после авторизации в приложении; публичного каталога файлов нет. Клиентские и прокси-кэши не должны сохранять приватное содержимое для общего использования.

Главная и поиск содержат только готовые, публичные, не скрытые видео. На канале и в плейлистах дополнительно могут отображаться приватные видео, к которым посетитель имеет доступ. Название, превью и счётчики недоступного ролика не раскрываются через эти экраны или API. Публичный плейлист не предоставляет доступ к приватным видео автоматически.

Отзыв разрешения и смена видимости применяются к новым запросам, включая запросы файла и превью. Уже полученные пользователем байты отозвать невозможно; это не DRM.

## Экраны и поведение

### Главная

Лента с пагинацией: превью, название, автор. Начальная сортировка — сначала новые. Есть переходы к поиску, каналу, загрузке и входу. Для пустой ленты предусмотрено отдельное состояние.

### Просмотр видео

HTML5-плеер с перемоткой, название, описание, автор, число лайков, комментарии с пагинацией, кнопка жалобы. Лайк одного пользователя на одном видео уникален; повторное действие позволяет снять лайк. Комментарии MVP — текстовые, без вложенных ответов и HTML. Автор комментария может удалить свой комментарий. Причины жалоб: спам, запрещённый контент, нарушение прав, другое; дополнительное пояснение — текст.

### Канал

Имя автора, доступные видео и плейлисты, кнопка подписки и отмены подписки. Одна подписка на пару пользователь/канал; подписка на свой канал запрещена. Редактирование чужого канала запрещено. Уведомления и отдельная лента подписок в MVP не входят.

### Поиск

Поиск по части названия без учёта регистра, пагинация и состояние «ничего не найдено». Описание, комментарии, рекомендации и полнотекстовый поиск не входят в MVP.

### Загрузка и управление своим видео

Выбор файла, название, описание и видимость. Видимость по умолчанию — приватная. Отображаются прогресс передачи, статус обработки и понятная ошибка. Владелец может редактировать метаданные, удалить видео, выдать и отозвать доступ. Имена файлов генерируются сервером, пользовательский путь не используется. Незавершённые загрузки и ошибки обработки не создают доступных роликов; временные файлы подлежат очистке. Удаление освобождает файл и превью и не оставляет доступных ссылок.

### Вход и регистрация

Регистрация по email и паролю, вход, выход. Email уникален без учёта регистра. Пароли и идентификаторы сессий не пишутся в логи. Ошибки входа не раскрывают наличие конкретного аккаунта. Ограничивается частота регистрации, входа и загрузок. Подтверждение email, восстановление пароля и внешний OAuth отложены; до публичного запуска нужно отдельно оценить этот объём.

### Модерация

Очередь жалоб с пагинацией и статусами `open`, `resolved`, `dismissed`. Скрытие/восстановление видео требует причины. Действия сохраняются в журнале: исполнитель, объект, время и причина. Повторная открытая жалоба того же пользователя на тот же ролик не создаёт дубликат. Владельцу нельзя обойти скрытие сменой приватности или метаданных. Панель назначения ролей администратора — отдельный минимальный экран.

### Плейлисты

Пользователь создаёт, переименовывает и удаляет свои плейлисты, добавляет доступные ему видео, удаляет их и задаёт порядок. В MVP плейлисты публичны, но содержимое всегда фильтруется по доступу посетителя. Закрытые плейлисты можно добавить позже.

## Эксплуатация и надёжность

- Документация API доступна на `/docs`, ошибки и схемы ответов описаны.
- Миграции запускаются штатной командой; обновление не удаляет данные.
- Секреты находятся вне Git, установщик не создаёт общеизвестные пароли.
- Одна документированная команда на чистой Ubuntu устанавливает зависимости, поднимает сервисы, применяет миграции и проверяет готовность. Повторный запуск не уничтожает данные.
- Для доступного извне HTTPS пользователь заранее предоставляет домен и направляет DNS на сервер; это внешняя предпосылка, её нельзя выполнить автоматически без данных пользователя.
- Диагностика учитывает БД, хранилище и обработчик видео раздельно; остановка обработчика не отключает просмотр готовых видео. Приём новых загрузок ограничивается доступным местом и очередью.
- Резервное копирование включает PostgreSQL, видео и превью; восстановление проверяется на отдельном окружении.
- Проверяются параллельные загрузки, недостаток места, обрыв соединения и перезапуск обработчика. Тяжёлая обработка не блокирует HTTP-процесс.

## Этапы реализации

Подробный актуальный порядок задач и критерии завершения находятся в
[плане разработки](development-plan.md). Список ниже обозначает общий объём MVP;
авторизация уже реализована до видеоподсистемы.

1. Каркас FastAPI, PostgreSQL, миграции, Compose, `/docs`, проверки готовности.
2. Технический сквозной сценарий видео в закрытой среде: загрузка, проверка, превью, постоянное хранение, воспроизведение и Range.
3. Регистрация, сессии, роли, владение, приватность и отзыв доступа; проверки запрета доступа. До завершения этого этапа доступ к загрузке и управлению извне закрыт.
4. Простой фронт: главная, просмотр, загрузка, вход, регистрация и поиск.
5. Каналы, подписки, плейлисты, лайки и комментарии.
6. Жалобы, модерация, назначение ролей и журнал действий.
7. Установщик Ubuntu, резервное копирование, восстановление и итоговые проверки приёмки. Локальный запуск через Compose поддерживается с первого этапа.

## За пределами первой версии

Рекомендательная система, прямые эфиры, монетизация, реклама, CDN, произвольные входные форматы, адаптивное качество/HLS, возобновляемые загрузки, уведомления, вложенные комментарии и мобильные приложения. Их отсутствие не отменяет подтверждённые требования выше.
